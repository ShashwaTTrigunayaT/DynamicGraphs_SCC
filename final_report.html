Major Impact

1. GPU-Only FB — Eliminate D2H/H2D in FB Phase

src_CUDA/scc_cuda_fb_gpu.cu (run_gpu_fb)

Problem. The FB phase downloaded every WCC component's node list from GPU to host, then re-uploaded them each level. On ljournal-2008 (8 FB levels), this was 40ms of pure transfer overhead.

Change. Use the WCC big buffer directly via pointer arithmetic. Scatter results stay in d_bulk_buf between iterations. Only tiny metadata uploaded per level.

// Instead of downloading WCC sets to host then re-uploading:
//   cudaMemcpy(tmp, w->d_set_nodes, w->count * sizeof(int), D2H);
//   cudaMemcpy(d_gpu_nodes, host_buf, ... H2D);

// Use WCC big buffer directly via pointer arithmetic:
if (can_use_wcc_buffer) {
    for (CUDAMyWork* w : all_works) {
        int offset = (int)(w->d_set_nodes - wcc_buf);
        cur.starts.push_back(offset);  // offset into wcc_buf
        cur.sizes.push_back(w->count);
        cur.colors.push_back(w->color);
    }
    d_gpu_nodes = wcc_buf;  // data stays on GPU
}

Key Numbers. ljournal-2008 H2D/D2H: 40.40ms → 0.35ms (−99%). ljournal-2008 TOTAL: 69.26ms → 28.69ms.

Major Impact — 99% transfer reduction. Single biggest optimization.

2. SMEM Hash Table — O(1) Node Lookup

src_CUDA/scc_cuda_fb_gpu.cu (gpu_fb_batch_kernel)

Problem. The batch kernel did a linear scan for (j = 0; j < comp_size; j++) if (smem_nodes[j] == k) for every BFS neighbor — O(comp_size) per lookup. With 2048-node components and dense edges, this hit 70ms on web-Stanford alone.

Change. Replaced O(n) linear scan with a 4096-slot Fibonacci hash table in shared memory (open addressing, linear probing). Hash nodes: smem_hash[node_id] = position. Lookup: hash → probe → found/miss.

// Build hash table: node_id -> position in smem_nodes
for (int i = tid; i < comp_size; i += stride) {
    int key = smem_nodes[i];
    unsigned h = (unsigned)key * 2654435761u;  // Fibonacci hash
    int slot = (int)(h >> 20) & (GPU_FB_HASH_SIZE - 1);
    while (atomicCAS(&smem_hash[slot], -1, i) != -1)
        slot = (slot + 1) & (GPU_FB_HASH_SIZE - 1);  // linear probe
}

// BFS neighbor: O(1) lookup instead of O(comp_size) scan
unsigned hk = (unsigned)k * 2654435761u;
int slot = (int)(hk >> 20) & (GPU_FB_HASH_SIZE - 1);
// probe smem_hash[slot] for k ... found in O(1) avg

Key Numbers. web-Stanford FB: 70.68ms → 16.18ms (−77%). SCC count unchanged: 29,876.

Major Impact — Made the GPU batch kernel viable.

3. BFS Neighbor Parallelization — 256 Threads Share Frontier

src_CUDA/scc_cuda_fb_global.cu (fw_bfs_level_kernel)

Problem. GLOBAL_BFS used a single thread to expand the frontier's neighbors across all edges. On wiki-Talk (459 BFS levels), this was 26.8ms of purely sequential scanning.

Change. All 256 threads share the work. Each thread claims a neighbor via atomicOr on a visited bitmap (separate from d_Color). A per-thread staging buffer (STAGE_SIZE=16) collects claimed nodes before flushing via a single atomicAdd, reducing atomic contention by 32x.

// Per-thread staging: 16 entries in registers (no local memory spill)
const int STAGE_SIZE = 16;
int staged[STAGE_SIZE];
int staged_cnt = 0;

// Distribute frontier nodes across blocks, neighbors across threads
for (int bi = blockIdx.x; bi < queue_size; bi += gridDim.x) {
    node_t t = d_queue[bi];
    for (edge_t nx = start + threadIdx.x; nx < end; nx += blockDim.x) {
        node_t k = d_node_idx[nx];
        if (d_Color[k] == base_color) {
            // Claim via atomicOr on visited bitmap (200KB, L2-resident)
            uint32_t old = atomicOr(&d_visited_bits[k >> 5], 1u << (k & 31));
            if ((old & bit) == 0) {
                d_Color[k] = fw_color;           // simple store, no CAS
                staged[staged_cnt++] = k;
                if (staged_cnt == STAGE_SIZE) {
                    int base = atomicAdd(d_next_count, STAGE_SIZE);
                    // ... copy staged to d_next_queue ...
                }
            }
        }
    }
}

Key Numbers. wiki-Talk GLOBAL_BFS: 26.8ms → 3.0ms (−89%). SCC count unchanged: 2,281,879.

Major Impact — Fixed the high-diameter graph bottleneck.

4. __ldg() + 4x Loop Unrolling — TRIM1 Compute Kernel

src_CUDA/scc_cuda_trim1.cu (compute_trim_targets_alive_counts_kernel)

Problem. The compact TRIM1 compute kernel scans ALL edges of remaining nodes. Each edge read d_Color[d_node_idx[e]] is a random access with ~300-800 cycle latency from VRAM.

Change. (1) Use __ldg() to route reads through the read-only data cache (bypasses L1, higher bandwidth for random access on Ada). (2) Unroll the loop 4x to pipeline independent loads, hiding latency via instruction-level parallelism.

// Unrolled 4x with __ldg for random d_Color reads.
// Each iteration issues 4 independent __ldg() loads that
// can be pipelined by the memory controller.
edge_t out_stride = blockDim.x * 4;
for (edge_t e = d_begin[n] + tid; e < out_end; e += out_stride) {
    int k0 = (e + blockDim.x * 0 < out_end) ? d_node_idx[e + blockDim.x * 0] : n;
    int k1 = (e + blockDim.x * 1 < out_end) ? d_node_idx[e + blockDim.x * 1] : n;
    int k2 = (e + blockDim.x * 2 < out_end) ? d_node_idx[e + blockDim.x * 2] : n;
    int k3 = (e + blockDim.x * 3 < out_end) ? d_node_idx[e + blockDim.x * 3] : n;
    out_cnt += (k0 != n && __ldg(&d_Color[k0]) == color) ? 1 : 0;
    out_cnt += (k1 != n && __ldg(&d_Color[k1]) == color) ? 1 : 0;
    out_cnt += (k2 != n && __ldg(&d_Color[k2]) == color) ? 1 : 0;
    out_cnt += (k3 != n && __ldg(&d_Color[k3]) == color) ? 1 : 0;
}

Key Numbers. TRIM1 (M6 Pokec): 11.25ms → 4.33ms (−61%). SCC count unchanged: 325,892.

Major Impact — Read-only cache + ILP for random-access patterns.

5. ALGO_TIME Inline Tracking

src_CUDA/scc_cuda.h (CUDA_TIMED_MEMCPY macro)

Problem. Getting fair GPU compute time required running nsys (~10s per run), parsing output, and manually summing kernel times — a 30-second workflow per code change.

Change. A macro wraps every hot-path cudaMemcpy with std::chrono timers (not CUDA events, which add ~10ms overhead). Accumulates H2D/D2H time. Program prints ALGO_TIME: X.XXms at the end of every run.

// Macro wraps every cudaMemcpy with std::chrono timing
// std::chrono overhead is ~100ns vs CUDA events ~10us
#define CUDA_TIMED_MEMCPY(dst, src, sz, kind) do {                              \
    auto _start = std::chrono::high_resolution_clock::now();                         \
    cudaError_t _err = cudaMemcpy(dst, src, sz, kind);                                 \
    auto _end = std::chrono::high_resolution_clock::now();                            \
    // ... error check ...                                                        \
    g_algo_memcpy_ms +=                                                                \
        std::chrono::duration<float, std::milli>(_end - _start).count();            \
} while(0)

// Printed at end of every run:
printf(">>>>ALGO_TIME: %.2fms (CUDA_PROFILE_TOTAL %.2fms - H2D/D2H %.2fms)\n",
       algo_ms, total_ms, memcpy_ms);

Key Numbers. Workflow time: ~30s (nsys) → 0s (printed inline). Zero-copy: one-liner grep ALGO_TIME for fair OpenMP comparison.

Major Impact — Developer productivity improvement. Now printed by every run.

Moderate Impact / Correctness

1. GPU Batch Kernel Bug Fixes (July 2026)

src_CUDA/scc_cuda_fb_gpu.cu

Problem. The GPU batch kernel produced systematically wrong SCC counts (~11K gap on indochina-2004). Four distinct bugs were found and fixed.

Fix A — Scatter ballot divergence. Divergent for (i = tid; i < num_src; i += stride) caused __shfl_sync undefined behavior on Ada SM 8.9+ independent thread scheduling. Fixed with uniform loop iterations: all threads execute the same trip count, skipping work with a conditional.

// Before: divergent loop (early-exited lanes cause __shfl_sync UB)
// for (int i = tid; i < num_src; i += stride) { ... __ballot_sync ... }

// After: uniform iteration count, all lanes converge before warp intrinsics
int total_iters = (num_src + stride - 1) / stride;
for (int iter = 0; iter < total_iters; iter++) {
    int i = tid + iter * stride;
    bool in_bounds = (i < num_src);
    unsigned active = __ballot_sync(0xffffffff, in_bounds);
    bool match = in_bounds && (d_Color[d_in_nodes[i]] == color);
    unsigned mask = __ballot_sync(active, match);
    // ... now safe: all active lanes converge at __ballot_sync
}

Fix B — Counting phase uniform loop. Same divergent-loop pattern in the counting section caused SUM_REDUCE (__shfl_xor_sync) to produce wrong sums. Fixed with uniform iteration count.

// Uniform counting loop: ALL threads execute same number of iterations
// Old: for (int i = tid; i < comp_size; i += stride)
//      Dead: early-exited lanes ran SUM_REDUCE while others still looping
int total_count_iters = (comp_size + stride - 1) / stride;
for (int iter = 0; iter < total_count_iters; iter++) {
    int i = tid + iter * stride;
    if (i < comp_size) {
        int c = d_Color[smem_nodes[i]];
        // classify as fw, bw, or base
    }
}
// Now safe to call SUM_REDUCE: all lanes in warp converged
SUM_REDUCE(local_fw);

Fix C — Color counter reset. d_fb_color_counter accumulated across levels without resetting. Could overflow and collide with SCC_FOUND (−2). Reset to max_color + 1024 each level.

Fix D — Hash-check-before-CAS. atomicCAS(&d_Color[k], ...) ran BEFORE checking if k was in the SMEM hash table — leaked fw/bw colors to nodes outside this component. Moved hash lookup before any CAS.

// Before: atomicCAS ran unconditionally, could leak color to wrong component
// int old = atomicCAS(&d_Color[k], base_color, fw_color);

// After: hash lookup FIRST, only CAS if k belongs to this component
unsigned hk = (unsigned)k * 2654435761u;
int slot = (int)(hk >> 20) & (GPU_FB_HASH_SIZE - 1);
int k_pos = -1;
while (1) {
    int pos = smem_hash[slot];
    if (pos < 0) break;
    if (smem_nodes[pos] == k) { k_pos = pos; break; }
    slot = (slot + 1) & (GPU_FB_HASH_SIZE - 1);
}
if (k_pos >= 0) {  // only CAS if k is in this component
    int old = atomicCAS(&d_Color[k], base_color, fw_color);
    // ...
}

Key Numbers. Scatter divergence: +~6,200 SCCs. Counting loop: +~1,300 SCCs. Total recovered: ~7,500. Remaining gap (indochina-2004): −4,675 (0.27%) — algorithmic, not a bug.

All 4 fixes kept. Remaining gap is algorithmic (level-by-level vs recursive).

src_CUDA/scc_cuda_fb_global.cu

11. Warp-Ballot Compact Build — 32x Fewer Atomics

src_CUDA/scc_cuda_trim1.cu

Problem. Compact set construction used a naive per-thread atomic increment to assign compact IDs. With 1.6M+ nodes, thousands of threads contended on the same counter.

Change. Each warp votes via __ballot_sync, then a single atomicAdd reserves IDs for all 32 threads. Threads compute individual IDs internally via __popc of lower lanes.

// Warp-ballot compact: 1 atomicAdd per warp instead of 32
__global__ void build_compact_from_all_kernel(...) {
    bool active = (idx < num_nodes) && (d_Color[idx] != SCC_FOUND);
    unsigned mask = __ballot_sync(0xffffffff, active);
    int warp_count = __popc(mask);
    if (lane == 0 && warp_count > 0)
        warp_base = atomicAdd(d_count, warp_count);
    warp_base = __shfl_sync(0xffffffff, warp_base, 0);
    int local_rank = __popc(mask & ((1u << lane) - 1));
    if (active)
        d_targets[warp_base + local_rank] = idx;
}

Kept — 32x fewer global atomics. Measurable improvement on large compact sets.

Problem. Ran all TRIM1 passes in a single kernel launch using grid.sync(). Blocks exit at different iterations (data-dependent), never reach a common sync point → indefinite deadlock.
