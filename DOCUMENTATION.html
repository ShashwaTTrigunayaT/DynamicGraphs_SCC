🔴 Current Problems & Status (Jun 18, 2026)

🔴 Problem 1: Missing SCCs in GPU FB Kernel (CRITICAL)

The GPU FB kernel is missing -16,394 SCCs on wb-edu and -36,077 on it-2004. Both graphs now have OpenMP ground truth. This is the #1 bug.

🟡 Problem 2: GLOBAL_BFS Slow on High-Diameter Graphs

wiki-Talk (+113%) and wikipedia-20070206 (+124%) have deep, narrow BFS frontiers (1-5 nodes/level) requiring many kernel launches. SMEM queue optimization attempted and failed.

Potential fix: Cooperative Groups persistent kernel with grid hardcapped to 142 SMs.

🟡 Problem 3: it-2004 GPU 3× Slower Than OpenMP

10.5s (OpenMP) vs ~33s (CUDA). The FB phase dominates for both. Fixing the GPU FB kernel correctness may also fix performance.

🐛 Known Issues

🔴 Issue 1: GPU FB Kernel Missing SCCs (UNFIXED)

wb-edu missing -16,394 SCCs (4,252,628 vs 4,269,022)
it-2004 missing -36,077 SCCs (30,456,018 vs 30,492,095)
Status: #1 priority — root cause unknown.

🔴 Issue 2: gm_graph Heap Corruption

Fix: exit(0) at end of main skips destructors.

🟡 Issue 3: OpenMP Method 2 Crashes on Large Graphs

Method 2 segfaults on wb-edu (TRIM12 phase). Use method 1 for OpenMP on large graphs. Method 1 skips TRIM12 and WCC but still gives correct SCC count.

🟡 Issue 4: TRIM12 & WCC Slower on GPU

Small workloads (8K-50K nodes) where GPU kernel launch overhead dominates.

🟡 Issue 5: cuda_get_new_color() Not Thread-Safe

Uses non-atomic _cuda_color_used++.

⚪ Issue 6: Benchmark Thermal Throttling

Run CUDA standalone for accurate timing.
